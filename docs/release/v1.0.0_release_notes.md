# RepoPilot Fix — v1.0.0 Official Release Notes

**Release Version:** `v1.0.0`  
**Release Date:** November 25, 2026  
**Status:** General Availability (GA)  

---

## 1. Overview & Vision

We are proud to announce the official **v1.0.0 release of RepoPilot Fix**, an open-source, evidence-driven autonomous software repair agent. RepoPilot Fix is released as a **local, demo-ready application** designed for local developer workstations, research, and hackathon demonstrations, rather than an independently audited multi-tenant production cloud SaaS. It represents a fundamental paradigm shift from conversational AI code assistants to a closed-loop verification agent that diagnoses, repairs, and mathematically verifies bug fixes inside isolated Docker sandboxes.

---

## 2. Key Capabilities in v1.0.0

- **AST-Driven Code Intelligence & Blast Radius:**
  - Standard library `ast` and Tree-sitter parsers construct cross-file dependency graphs without cloning git histories.
  - Static blast radius calculation traces downstream callers and flags suggested regression test suites.
  - Interactive, lightweight pure-SVG visualizer in the Next.js UI with directed cycle detection.
- **Proof-of-Fix Dual Docker Sandboxes:**
  - Baseline sandbox confirms defect reproduction on unpatched code.
  - Patched sandbox executes candidate unified diffs and computes delta failures (`new_failed_test_ids`).
  - Classifies outcomes into deterministic verdicts (`VERIFIED_FIX`, `FIX_FAILED`, `REGRESSION_DETECTED`, `PATCH_APPLICATION_ERROR`).
- **Cryptographic Human Approval & Fenced Worker Queue:**
  - Binds candidate diffs to immutable SHA-256 specification hashes requiring human sign-off.
  - Background worker loop utilizes PostgreSQL `SELECT FOR UPDATE SKIP LOCKED`, 5-second heartbeats, and fencing tokens to eliminate split-brain execution across worker replicas.
- **Docker Compose & Self-Hosted Configuration:**
  - Multi-service composition (`db`, `api`, `worker`, `web`) with healthchecks and persistent storage.
  - Unprivileged multi-stage containers (`repopilot:1000`, `nextjs:1001`).
  - Air-gapped container sandboxes (`--network none`, `--read-only`, tmpfs, resource limits).
- **Idempotent GitHub PR Integration:**
  - Safe external PR export gated by human approval and verified fix status.
  - Forward schema migration `0009` with safe pre-flight duplicate detection.

## 3. Verified Benchmark & Quality Metrics

- **Repair Success Rate:** **85.0% (17/20)** across curated defect-pattern fixtures distilled from mature Python libraries (Click, Requests, Bottle, Marshmallow, Pydantic, HTTPX, Jinja, Werkzeug, etc.).
- **Retrieval Precision:** **100% Recall@5** and **0.925 Mean Reciprocal Rank (MRR)**.
- **Regression Rate:** **0.0% (0/18)** unexpected regressions introduced on executed patches.
- **Multi-File Repairs:** **100% (3/3)** complex multi-file fixes verified.
- **Automated Test Suite:** **361 Total Tests** (327 backend tests including 3 real Docker sandbox tests; 34 frontend tests) passing with 0 errors.
- **Deterministic Docker Verification Baseline:** Baseline container reproduces defect with exit code 1 (2 failures: `test_power_positive`, `test_power_zero`), patched container verifies fix with exit code 0 (6 passes, 0 regressions), verdict `VERIFIED_FIX` in 16.91s.
- **Runtime Verification Safeguards:** Zero discovered tests strictly yield `INCONCLUSIVE` and can never produce a verified fix; PR creation and patch export are strictly gated on `VERIFIED_FIX`.

## 4. Supported Deployment Modes

1. **Local Development Mode:**
   - Next.js frontend (`localhost:3000`), FastAPI backend (`localhost:8000`), local PostgreSQL instance.
   - Zero-cost offline mode with `CHAT_PROVIDER=mock`.
2. **Production Docker Compose Mode:**
   - Isolated four-service deployment (`repopilot-db`, `repopilot-api`, `repopilot-worker`, `repopilot-web`).
   - Private worker boundary separating the Docker daemon from public web traffic.

---

## 5. Known Limitations

- **Headless Server Browser Automation:** Visual browser testing (console logs, mouse click tracking) is marked pending on headless Linux build servers due to the absence of local Chrome/Chromium binaries; all 15 user journey stages are verified via live HTTP route and API integration suites.
- **In-Memory Rate Limiting:** Rate limiting uses an in-memory token bucket suitable for single-instance deployments; distributed horizontal scaling with Redis is targeted for v1.2.0.
- **Python Sandbox Optimization:** Docker sandboxing currently specializes in Python test runners (`pytest`, `unittest`).

## 6. Upgrading from Pre-Release Versions

1. Pull the `main` branch.
2. Review and apply database migrations explicitly:
   ```bash
   alembic -c apps/api/alembic.ini upgrade head
   ```
3. Restart application containers with `docker compose up -d --build`.
