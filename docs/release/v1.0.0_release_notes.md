## 1. Executive Summary & Release Scope

We are proud to announce the official **v1.0.0 release of RepoPilot Fix**, an open-source, evidence-driven autonomous software repair agent.

> [!IMPORTANT]
> **Deployment Classification — Local Demo-Ready:**  
> RepoPilot Fix v1.0.0 is officially released and labeled as a **local demo-ready application**. It is architected for local developer workstations, educational research, and interactive hackathon demonstrations, rather than an independently audited multi-tenant public SaaS.

RepoPilot Fix represents a fundamental paradigm shift from conversational AI code assistants to a closed-loop verification agent:
1. **Investigates:** Uses Tree-sitter and standard library `ast` parsers to build symbol dependency graphs and trace bug blast radiuses without cloning full git histories.
2. **Synthesizes:** Formulates grounded hypotheses with strict 1-indexed source line citations and generates minimal unified diff patches.
3. **Cryptographically Secures:** Binds candidate patches, test commands, and container image tags into immutable SHA-256 specification hashes requiring human approval.
4. **Empirically Verifies:** Executes dual Docker sandboxes (baseline reproduction vs. patched verification) under strict air-gapping (`--network none`, `--read-only`, non-root, resource caps) to mathematically prove the fix.
5. **Safely Exports:** Enables clean patch downloads and idempotent PR creation strictly gated on verified fix verdicts.

### A. Deterministic Fixture Verification
- **Purpose:** Reliable, zero-cost, reproducible demonstration on any developer workstation or offline environment.
- **Fixture:** `demo-calculator` featuring an operator defect in `power(base, exponent)` (`*` multiplication instead of `**` exponentiation).
- **Execution:**
  - **Baseline Container:** Runs pytest test suite against unpatched code. Exits with code 1 and captures 2 failed tests (`test_power_positive`, `test_power_zero`).
  - **Patched Container:** Applies candidate fix diff and re-executes tests inside an identical container. Exits with code 0 (6 passed tests, 0 regressions).
  - **Outcome:** Resolves defect with `VERIFIED_FIX` verdict in 16.91s without requiring an internet connection or paid API keys.

### B. Live AI Evaluation
- **Purpose:** Rigorous empirical evaluation of autonomous LLM reasoning across complex software bugs.
- **Model & Configuration:** Evaluated using Google AI Studio (`models/gemini-flash-lite-latest`) on the Free Tier ($0.00 spend, zero billing required).
- **Methodology:** The LLM receives only untrusted issue descriptions and retrieved AST code blocks with 1-indexed line numbers—no solution diff or golden patch is provided.
- **Benchmark KPIs (20 Defect-Pattern Fixtures):**
  - **Verified Repair Rate:** **85.0% (17/20)** verified in dual Docker sandboxes.
  - **Retrieval Precision:** **100% Recall@5** and **0.925 Mean Reciprocal Rank (MRR)**.
  - **Regression Rate:** **0.0% (0/18)** unexpected regressions introduced.
  - **Multi-File Repairs:** **100% (3/3)** complex multi-file fixes verified.

### C. Simulated Pull Request Creation (Demo Mode — PR #24)
- **Purpose:** Realistic demonstration of pull request lifecycle and export workflows without requiring GitHub Personal Access Tokens or risking external repository pollution.
- **Functionality:**
  - Guest and demo users can simulate PR creation (PR #101) directly inside the local PostgreSQL database for verified demo fixtures.
  - Generates realistic branch names (`fix/issue-1-power-calc`) adhering to strict Git ref standards.
  - **Idempotency:** Re-running simulation returns existing PR metadata with `status='already_exists'` and `is_simulated=True` without duplicate database rows.
  - **Strict Security Boundary:** Guest sessions attempting to write to real external GitHub repositories are rejected with `HTTP 403 Forbidden`. External PR creation strictly requires verified fix status and valid credentials.

To facilitate evaluation and deployment without incurring unexpected cloud charges or security vulnerabilities, we have audited the application requirements across major platforms:


### 1. Frontend Web Client (Vercel)
- **Eligibility:** 100% free on **Vercel Hobby Tier** ($0/month).
- **Setup Requirements:**
  - Set root directory to `apps/web` (or workspace build `npm run build --workspace @repopilot/web`).
  - Configure `NEXT_PUBLIC_API_BASE_URL` pointing to the backend API domain.
  - Enable Next.js rewrites (`next.config.ts`) to proxy `/api/:path*` to the backend if cookie-based cross-origin authentication is desired.
- **Cost & Charge Protection:** Vercel Hobby does not allow automated overage billing; usage halts if 100 GB bandwidth limit is reached, guaranteeing zero surprise charges.

### 2. Backend API Service (Render)
- **Eligibility:** 100% free on **Render Free Web Service** ($0/month).
- **Setup Requirements:**
  - Build command: `python -m pip install -e "./apps/api[dev]"`
  - Start command: `uvicorn repopilot_api.main:app --host 0.0.0.0 --port $PORT`
  - Environment variables: `DATABASE_URL`, `FRONTEND_URL`, `CORS_ORIGINS`, `COOKIE_SECURE=true`.
  - Set `ALLOW_DOCKER_VERIFICATION_EXECUTION=false` (Render web instances cannot access Docker).
- **Caveats & Charge Protection:**
  - Free instances spin down after 15 minutes of inactivity; initial cold start takes ~50 seconds.
  - Render free tier grants 750 free instance hours/month. Render suspends service rather than charging credit cards when limits are hit.

### 3. PostgreSQL Database (Neon)
- **Eligibility:** 100% free on **Neon Free Tier** ($0/month).
- **Setup Requirements:**
  - PostgreSQL 16 serverless instance with 0.5 GB storage.
  - Connection string format: `postgresql+psycopg://[user]:[password]@[endpoint].neon.tech/[dbname]?sslmode=require`.
  - Run database migrations explicitly via Alembic: `alembic -c apps/api/alembic.ini upgrade head`.
- **Caveats & Charge Protection:**
  - Neon free tier does not require a credit card and provides 100% zero-charge protection.
  - Compute endpoints auto-suspend after 5 minutes of inactivity (~500ms cold start latency on query).

### 4. Secure Private Docker Worker Boundary (Security Critical)
> [!CAUTION]
> **Docker Daemon Security Notice:**  
> The Docker daemon socket (`/var/run/docker.sock`) grants root-equivalent control over the host system. **Under no circumstances should the Docker socket be mounted to public web services, Vercel, or public Render web containers.**

- **Architecture Boundary:**
  - The verification worker (`repopilot-worker`) runs in a private execution perimeter with **zero inbound public network ports** (zero public ingress).
  - The worker initiates outbound database queries using `SELECT FOR UPDATE SKIP LOCKED` to claim approved verification jobs.
  - Sandboxes are spawned locally with strict isolation: `--network none`, `--read-only`, non-root UID `1000:1000`, 512MB RAM cap, 1 CPU cap, and 100 PID limit.
- **Genuinely Free Worker Deployment Options:**
  1. **Local Developer Workstation (Recommended):** Run the worker locally via `docker compose up -d worker` connecting to the local or remote Neon database. 100% free, 0 risk of cloud billing.
  2. **Oracle Cloud Always Free VM:** Provision an Always Free ARM Ampere instance (4 cores, 24 GB RAM, 200 GB storage) with no public ingress ports, running Docker natively at $0/month permanently.
  3. **Simulated Verification Mode:** For purely serverless cloud demos without a Docker host, configure `ALLOW_DOCKER_VERIFICATION_EXECUTION=false` to execute deterministic mock verification safely.

## 5. Exact Step-by-Step Deployment Instructions

### Recommended Deployment: Local Production Docker Compose (Zero-Cost & Fully Isolated)

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/Mehndi-Hassan28/repopilot-fix.git
   cd repopilot-fix
   ```

2. **Configure Environment:**
   ```bash
   cp .env.example .env
   ```
   *(All defaults in `.env.example` are pre-configured for instant zero-cost local execution with `CHAT_PROVIDER=mock`)*.

3. **Build and Launch Containerized Stack:**
   ```bash
   docker compose up -d --build
   ```

4. **Apply Database Migrations:**
   ```bash
   docker compose exec api alembic -c apps/api/alembic.ini upgrade head
   ```

5. **Verify System Health:**
   ```bash
   # Check Backend API Health
   curl -f http://localhost:8000/health
   # Expected output: {"status":"ok","service":"repopilot-api"}

   # Check Web UI
   curl -I http://localhost:3000/
   # Expected output: HTTP/1.1 200 OK
   ```

6. **Access Application:**
   Open [http://localhost:3000](http://localhost:3000) in your web browser. You can immediately launch the interactive demo, explore the AST dependency graph, inspect issues, approve verification runs, and simulate pull request creation.
